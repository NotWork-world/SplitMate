# Deploy the SplitMate server (Render + Neon, free tiers)

The app talks to `https://splitmate-api-ya67.onrender.com` by default (`mobile/src/config.ts`). This guide puts the API there.

## 1. Database on Neon

1. Sign up at <https://neon.tech> and create a project (region: **AWS Asia Pacific (Singapore)**, close to Render's Singapore region).
2. Copy the **connection string** (Dashboard → Connection details). It looks like `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

The free tier doesn't expire; the database pauses when idle and wakes on the first query.

## 2. Receipt photos: nothing to set up

A bill photo is only kept while the bill is being split and is deleted as soon as the bill is
finalised or cancelled (unused uploads after two days). The items, prices and tax are saved in the
database, so nothing is lost. The container's own disk (`SPLITMATE_STORAGE_BACKEND=local`) is
therefore enough. A redeploy only removes photos of bills still being split. If you ever want to
keep photos, switch to `s3` with a private Cloudflare R2 bucket and the `SPLITMATE_S3_*` variables.

## 3. API on Render

1. <https://dashboard.render.com> → **New + → Blueprint**, pick **NotWork-world/SplitMate**, branch `main`. Render reads [`render.yaml`](../render.yaml): one Docker web service, `splitmate-api`.
2. Fill in the variables marked *sync: false*:

| Variable | Value |
|---|---|
| `SPLITMATE_DATABASE_URL` | Neon connection string |
| `SPLITMATE_GOOGLE_CLIENT_IDS` | Web OAuth client ID ([google-sign-in.md](google-sign-in.md)); leave empty to hide Google sign-in |
| `SPLITMATE_PUBLIC_BASE_URL` | `https://<service>.onrender.com` (no trailing slash). Invite links use it. |

`SPLITMATE_JWT_SECRET` and `SPLITMATE_SIGNING_SECRET` are generated by Render. The server **refuses to start** in production with default secrets or SQLite.

3. Deploy. The container runs `alembic upgrade head` before starting, so the schema is always migrated; tables are never auto-created.
4. Check `https://<service>.onrender.com/api/health` → `{"ok": true, ...}`, and the API docs at `/api/docs`.

If Render gives a different hostname, either change `DEFAULT_API_URL` in `mobile/src/config.ts` before building, or set it in the app under **Settings → Advanced → Server**.

## Free-tier notes

- Render sleeps after 15 minutes idle; the first request takes ~50 s. The app waits up to 70 s and shows a clear message if it times out. A free uptime monitor hitting `/api/health` every 10 minutes keeps it awake.
- One instance: the in-process rate limiter is per instance. Move it to Redis before scaling out.

## Local development

```bash
cd server
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt     # macOS/Linux: .venv/bin/pip
.venv/Scripts/alembic upgrade head                     # SQLite file by default
.venv/Scripts/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

PostgreSQL locally (what CI-style checks use):

```bash
docker run -d --name splitmate-pg -e POSTGRES_USER=splitmate -e POSTGRES_PASSWORD=splitmate -e POSTGRES_DB=splitmate -p 54329:5432 postgres:17-alpine
set SPLITMATE_DATABASE_URL=postgresql://splitmate:splitmate@localhost:54329/splitmate
```
